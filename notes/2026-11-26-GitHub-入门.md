## 学到的概念

| 概念 | 一句话理解 |
|---|---|
| Repository（仓库） | 项目文件夹 + 它的全部历史版本 |
| Commit（提交） | 一次「存档」，带说明、作者和时间 |
| Branch（分支） | 平行开发线，改坏了不影响主线 |
| Pull Request（PR） | 「我改好了，请合并」的申请单，可以评审 |
| Issue（议题） | 任务单 / Bug 单 / 讨论帖 |
| clone | 把远程仓库复制到本地 |
| push | 把本地的提交送到远程 |
| pull | 把远程的新提交拉回本地 |
| fork | 把别人的仓库复制一份到自己名下 |
| star | 收藏 + 点赞 |
| watch | 订阅这个仓库的动静 |

## 跑通的一条工作流

```bash
git clone <仓库地址>        # 第一次：把仓库拿到本地
git add -A                  # 把改动放进暂存区
git commit -m "说明"        # 存档，写清楚改了什么
git push                    # 推到 GitHub
```

## 手感的记忆点

- commit 信息要写成「做了什么」，例如 `docs: 新增第一篇学习笔记`，别写「update」
- 多人协作时，push 之前先 `git pull`，避免冲突
- 改大功能前先开分支，主分支永远保持能用
